I
01 · The Vibes Problem

Vibes
don’t scale.

“There’s no way for anybody to prove whether something was fixed or that it’s actually failing.” You have vibes to go off of.

Monday

You change something in your prompt and ship it. It overall feels better.

Tuesday

Ship it again. You don’t really have a way to know, but things look good.

A week later

The use case you shipped a fix for is broken.

Next week

The problem keeps getting worse, and nobody can prove it either way.

Without evals, you can’t…

01Detect regressions when you change a prompt
02Objectively compare prompts or model versions
03Know if a new model is better for your use case
04Put official quality gates into CI as you ship
II
02 · Is an Eval Just a Unit Test?

Not quite. Not even close.

Logs
≠
Tests

Traditional softwareThe unit test

  • One input, one correct output
  • You can read all of the logic in the code
  • Pass or fail, cleanly

AI agentThe eval

  • Many valid outputs, so no single expected answer
  • You cannot read the logic. It “comes out after in the form of traces”
  • Judge multiple criteria: the day-by-day itinerary, the budget breakdown
The hard pill is you kind of need traces, you need observability to actually do your evals.— SallyAnn DeLucia

IV
04 · A Field Guide

Seven ways to grade an agent.

LLM as a judge is where we take a secondary LLM and ask it to grade some aspect of our agent: QA, summarization, relevance. You get a label and an explanation, the reasoning behind the label, so you are not taking it at face value. This is today’s focus.

Decision models are new, and DeLucia thinks they will be “a huge part of evals in the future.” They are cheap and fast: a question goes in, a probability and a true/false or label comes out. No explanation, though.

Code evals suit deterministic tests: is a word in the output, is something valid JSON. ROUGE and BLEU scores live here too. Annotations are golden truths on golden datasets, sometimes synthetic.

Agent as a judge is a newer type, seen over roughly the last six months. A full agent evaluates something in a different agent, which suits super-complex success criteria. User feedback and business metrics round out the production side.

Across the life cycle

The first four travel with you

LLM judge, decision model, code and annotations work in development and production. Don’t throw away your dev investment.

Production

The last three live in prod

Agent-as-judge leans complex; user feedback and business metrics come once real users arrive.

06 · Define What Good Means

Write down what good means.

Judge one quality per eval START WITH ONE · ADD MORE LATER

Vague vs. concrete

Helpful, accurate, good response.

Instead: follows the user’s follow-ups, matches the requested number of days, keeps totals within the stated budget.

Six things to write down

  1. The task
  2. What success looks like
  3. What failure looks like
  4. What is being judged
  5. Three bullets for pass
  6. Three bullets for fail

The worked example

Task: user sends a follow-up about their trip.

Success: answers the follow-up directly using the trip’s details.

Failure: falls back to a generic budget.

Why one-liners aren’t enough: these bullets become the judge’s prompt. Research shows an LLM judge handles one criterion at a time best.

Treat it like describing success to a coworker or a stakeholder: be that specific.

VII
07 · Build the Judge

Turn criteria
into a prompt.

01

Filter the spans

Root spans: parent ID = null. Judging a tool call? Filter by name.

02

Save to a dataset

Select the spans you’re judging and add them to a new dataset.

03

Open the prompt playground

Not the agent playground, which tests your agent end to end.

04

Write the template

Start with a blank eval. Open with the job, add the data, paste in your pass/fail bullets.

05

Map variables

Connect to your exact data, so evals stay flexible when a dataset and traces name fields differently.

06

Set labels

Correct/incorrect, or more. Pick the optimization direction. Keep explanations on.

07

Run and iterate

Run it (the demo used 4.1 mini), agree or disagree with the outputs, tweak the prompt, repeat.

08

Save the evaluator

It’s then available across the platform, for the demo project or any app you bring in.

Prompt tip“I always kind of center it in its job.” Open with what the LLM is evaluating, then provide the data, then the criteria.
ShortcutInstrument your own app by letting your coding agent figure it out, then nudge it along. Alex can also run the playground, read results and update the prompt for you.
VIII
08 · Close the Loop

An eval is a start, not a finish.

Alex

Runs the playground, looks at the results, updates the prompt and repeats. Best used after your first pass.

Signal

A managed agent that looks at your traces, finds issues and even makes fixes.

Alignment

Annotate the examples in your dataset, run the eval, and check that it matches human feedback.

Online evals

Put the eval in a task that runs continuously over your traces. Every trace sent in is evaluated automatically, so you can monitor.

Every stakeholder evaluates the agent.

A metric tells you that something might be broken, but evals tell you what the actual failure mode is.— SallyAnn DeLucia, Arize AI
